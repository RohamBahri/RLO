## Scope and constraints

- One shared policy trained from independent unlabeled CVRP instances. No external solver/heuristic tours, teacher next actions, imitation targets or oracle Q labels in training. Exact and heuristic references are evaluation only.
- Preserve the masked, unlimited-fleet n=10/20/30 Euclidean CVRP in the primary comparison. No new constraint family may silently enter this comparison.
- Keep exact/PyVRP frozen references; no final test-data use until method configuration/selection is frozen.
- Document all transition counts (on-policy, baselines, replay collection, Dyna simulation, search/Q estimation, action simulations), optimization updates, wall-clock, and validation/inference effort. Replay *reuses* data, so also report unique interactions, replay updates, and total simulated transitions separately.
- Prioritize meaningful budgets, not short performance pilot runs. Software smoke runs for finite loss, transition accounting, legal-action handling and checkpoint round-tripping are **correctness checks**, not statistical evidence.
- Three seeds minimum per substantive arm, same common validation cases/metrics, predeclared hyperparameters; no cherry-picking seeds or best-of-run validation checkpoints. Plot complete score-versus-transition and quality-versus-wall-time curves with uncertainty.
- Initial comparison: single-start greedy validation cost scaled by sqrt(n) averaged over n=10,20,30, with separate per-size metrics. Secondary: all-n-start greedy, common best-of-K and inference cost; savings and PyVRP evaluation-only. Distinguish per-instance percentage gap from ratio of mean costs.

## Wave 2: missing learning-method families — build while Wave 1 trains

Use the same data distribution, policy width and splits; preserve exact policy definitions and numerical validation checks. Each independently trained full comparison uses three seeds and target 50M counted environment transitions. Only correctness failures block a run; poor short-run validation is **not** a method-elimination gate.

1. **Off-policy model-free**: one well-defined masked, graph-generalizing Double-DQN (or equivalently explicitly specified off-policy Q/value control) with replay and target network. Prove that the target uses only legal next actions, terminal rewards include forced moves, and stale target predictions are detached. Distinguish replay updates from unique environment transitions. This family is genuinely missing in current `main`; do not relabel A2C or critic-only Dyna as an off-policy control result.
2. **Dyna / simulation-based replay**: reproducible experience-only synthetic trajectories from encountered states via the known deterministic CVRP simulator; include the historical critic-only/value-head Dyna variant and one explicitly off-policy-corrected policy/value update variant if feasible. Use version/staleness diagnostics. Compare at common *total simulated transitions* and separately common on-policy interactions. Since the CVRP transition law is given exactly, this is **model use**, not demonstrated learning of a transition model.
3. **MBPI**: own-rollout action-value estimates, KL-constrained improvement, n<=10 exact action-value and action-regret metrics for diagnostics only; no exact values in optimization targets. Use a common Wave-1 checkpoint as initial policy and compare to **the same checkpoint continued under its original training method**, at matched additional compute; include pretraining compute when plotting lifetime compute. Sample new independent instances throughout training.
4. **Auxiliary predictions / GVFs**: objective-relevant auxiliary returns from experience; no trivial always-feasible "can complete" label in unlimited-fleet CVRP. A feasibility-completion GVF requires a separately predeclared *restricted-fleet* problem with genuinely nontrivial feasibility, a verified generator/checker, and a matched no-GVF control on that new environment. Do not mix results from this changed problem with primary CVRP comparisons.
5. **Hierarchical policy**: high-level route-close/continue vs low-level legal-customer choice, matched masked environment and model capacity as closely as possible. Separate functional equivalence checks and differences in trainability.

Build tests/implementations in parallel with GPU Wave 1. New-code unit tests, small stochastic-gradient checks, replay/policy consistency, and one same-seed smoke job are legitimate correctness gates. Method decisions use substantial budgets.

## Wave 3: architecture, self-improvement and inference — parallel once anchors exist

- **Representation**: historical raw/MLP/codebook embeddings and selected distance-bias / static-vs-dynamic encoder / glimpse ablations, one axis at a time around a frozen anchor. At least three seeds and meaningful training budgets for the selected ablations. Do not sweep every combinatorial architecture combination.
- **Self-improvement / search-trained methods**: distinguish return-derived MBPI from sampled-best self-training, AlphaZero-like self-play/search target training, and critic-only Dyna. Only self-generated simulations/returns may supervise; no external solver demonstrations. Require reproducibility, valid target distributions, and matched simulation/transitions budgets.
- **Inference only**: for fixed trained checkpoints compare greedy, multistart, best-of-K sampling, beam, MCTS, and small-residual exact handoff. Report tour quality and inference time by size; exact handoff is explicitly a *hybrid solver* not a purely learned solver. These are separate from training-method claims.

## Statistical protocol and allocation

At 10M, 25M, 40M, 50M transitions, evaluate all arms (or interpolate nearby predeclared checkpoints; do not use best sampled checkpoint retrospectively). Plot mean and all three seeds; report paired per-instance improvements, dispersion and uncertainty, per-size and generalization tests. Record nonfatal failures and method instability. Decide on 100M+ extensions *after* comparing trends at 40M to 50M: the previously agreed approximately 0.2% late improvement criterion can justify extension but does not establish convergence by itself.

Run evaluation on frozen **validation**, and only once methods, model selection and inference budgets are frozen, use the nine-configuration **test** grid. Include both solution quality and measured wall-time, GPU model/CPU configuration, number of updates, simulated transitions and distinct instances. The final research choice must balance generalization, training/inference efficiency and method-specific value over cheap savings, not simply ranking neural baselines.

## True gates, not tiny research experiments

1. **Correctness**: legal-action/forced-step rewards, training-target origin, independent solution validator, non-leaking train/validation/test streams, reproducible replay and complete compute accounting.
2. **Operational**: GPU job can load and run on A100; no overwrite of existing results; checkpoints/backups for jobs likely to exceed allocation limits. Wave 1 is a fresh 50M job and does not pretend to resume.
3. **Research design**: warm starts use matched controls; changes in capacity/vehicle constraints explicitly segregated from current comparison.

A failed gate is a code or protocol failure, not a conclusion that an algorithm is weak.
